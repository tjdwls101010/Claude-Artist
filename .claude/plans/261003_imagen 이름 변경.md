# artist 스킬 → imagen 이름 변경

## Context

성진이 `.claude/skills/artist`를 `/imagen`으로 부르고 싶어 한다. 스킬 이름은 폴더명·`name:`만이 아니라 코드 트리 규칙(패키지 이름 = 스킬 이름, `tests/structure.py`의 `PACKAGE`)과 사용자 설정의 허용 규칙(D22)에도 박혀 있어서, 폴더만 바꾸면 구조 테스트가 깨지고 두 번째 턴부터 `cli.py` 호출마다 권한 창이 뜬다. 그래서 스킬이 밖으로 드러내는 이름을 한 번에 같이 바꾼다.

## 바꾸는 것

- 폴더: `.claude/skills/artist/` → `.claude/skills/imagen/` — `git mv`가 아니라 `mv`로 통째 옮긴다. `data`는 gitignore된 Obsidian 심볼릭 링크(`→ 🖼️Creatives`)라 `git mv`로는 따라오지 않는다. 옮긴 뒤 `data` 링크가 그대로 살아 있는지 확인.
- `SKILL.md`: `name: imagen`, H1 `# imagen`. 본문에 `artist` 언급은 이 두 줄뿐.
- Python 패키지: `scripts/artist/` → `scripts/imagen/`, 모든 `from artist …`/`import artist…`를 `imagen`으로 (`cli.py`, `record.py`, `generate.py`, `sheet.py`, `inspect.py`, `compose.py`, `doctor.py`, `ledger/*`, `__init__.py` docstring, `cli.py` docstring). `imagen`은 표준 라이브러리 모듈과 겹치지 않는다.
- 환경 변수: `ARTIST_DATA` → `IMAGEN_DATA`, `ARTIST_CHROME_PATH` → `IMAGEN_CHROME_PATH` (`paths.py`, `chrome/__init__.py`, `cli.py` epilog, `tests/conftest.py`, `tests/test_compose.py`). 셸·설정 어디에도 이 변수를 쓰는 곳이 없음을 grep으로 확인함.
- 내부 식별자: `chrome/probe.py`의 `data-artist-*` 속성·`artist-probe` 태그, `sheet.py`의 localStorage 키 `artist-sheet:` → `imagen-*`. (기존 시트는 다음 `record` 때 다시 써지며 스크롤 위치만 한 번 잊는다. `data/` 안의 기존 HTML은 손대지 않는다.)
- 테스트·설정: `tests/structure.py`(`PACKAGE = "imagen"`, docstring), `tests/conftest.py`·`tests/test_structure.py`의 경로와 `artist` 패키지 경로·import 문자열, 나머지 테스트의 `from artist import …`, `pyproject.toml`의 `pythonpath`, `.gitignore`의 `.claude/skills/artist/data`.
- 개발 기록: `docs/artist-design.md` → `docs/imagen-design.md`, 제목과 `.claude/skills/artist` 경로만 갱신. 성진 발화 인용("artist로 만드는 이미지는…")은 원문 그대로 둔다.
- 사용자 설정(`update-config` 스킬로): `~/.claude/settings.json` 14행 허용 규칙의 경로를 `…/.claude/skills/imagen/scripts/cli.py`로.

## 바꾸지 않는 것

- 레포 이름·`pyproject.toml`의 `name = "claude-artist"`·`uv.lock`, `tests/test_generate.py`의 "claude artist" 주석 — 레포(`Claude-Artist`)를 가리키는 이름이다.
- `.claude/plans/`의 과거 계획서, `.tmp/`, `data/` 안의 작업물 — 이력이다.

## 절차

`TaskCreate`로 아래 단계를 트래커에 올리고 단계마다 `TaskUpdate`. 브랜치 `refactor/rename-artist-to-imagen`, PR 제목 `refactor: artist 스킬 이름을 imagen으로 변경`, 템플릿이 없으므로 `## 무엇을 바꿨나 / ## 왜 / ## 영향 / ## 검증`, `gh pr merge --squash`.

1. 폴더·패키지 이동 — 완료: `ls .claude/skills/imagen/scripts/imagen`이 모듈을 보여 주고 `readlink .claude/skills/imagen/data`가 Creatives를 가리킴.
2. 코드·테스트·설정 파일 치환 — 완료: `grep -rn -i artist --exclude-dir=.git --exclude-dir=.tmp --exclude-dir=__pycache__ --exclude-dir=plans .`에 남는 것이 위 "바꾸지 않는 것"과 docs의 인용뿐.
3. 사용자 설정 허용 규칙 갱신 — 완료: `~/.claude/settings.json`에 `skills/imagen/scripts/cli.py` 규칙이 있고 `skills/artist` 규칙이 없음.
4. 검증 후 커밋·PR·머지 — 완료: 아래 검증 전부 통과, PR 머지됨.

## 검증

- `uv run pytest` 전체 통과(구조 테스트 포함).
- `uv run ".claude/skills/imagen/scripts/cli.py" --help`, `… doctor` 정상 종료(doctor는 data 링크·codex·Chrome을 확인).
- `claude plugin validate --strict .claude/skills` exit 0.
- 새 세션에서 `/imagen`이 목록에 뜨는지는 성진이 확인(이 세션에서는 스킬 목록이 다시 로드되지 않음).
