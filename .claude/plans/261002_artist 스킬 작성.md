## Context

성진은 의원실 홍보 비서관이고 디자이너가 아니다. 결과물을 보면 정확히 판정하지만 디자인 어휘가 없다. `artist`는 Claude Code 안에서 gpt-image(Codex 내장 `image_gen`)로 **성진 마음에 드는** 이미지를 얻는 과정 전체를 맡는 아트 디렉터 스킬이다. 의도를 합의하고, 서로 다른 시안을 여러 장 보여 주고, 반응을 받아 고치고, 확정한다.

성공 기준은 퀄리티 하나다. AI 티(이유 없는 구도·광원·고급스러운 척하는 색), 촌스러움, 어색한 디테일 없이 의도에 맞아야 하고, 최종 판정자는 성진의 눈이다. 미적 중심은 "그래픽 디자이너가 일러스트로 정성스럽게 만든" 이미지이고 실사는 막지 않는다. 글자가 곧 내용인 작업(발언 템플릿·법안 요점)은 이미지 모델이 아니라 Claude가 HTML로 짜고, GPT는 그 안에 놓일 요소만 만든다.

옛 스킬(`.tmp/old-skills`, harness-creator로 만듦)은 실측으로 얻은 지식이 값지지만, 본문 상당량이 출처 기록·규칙 변론이고 코드가 공통 트리를 따르지 않으며 일부 사실이 낡았다. 그래서 **skill-maker 프레임으로 전면 재작성**한다. 지식은 현재 모델로 재검증해 옮기고, 위계·코드·성진에게 보여 주는 통로는 새로 도출한다. SKILL.md는 장르별 제작법이 아니라 **기본 미적 감각**(취향과 원리, 모델의 버릇, 판단의 경계, 합의 방식)에 집중한다.

이 계획서는 Codex(gpt-6-astra, high) 적대 검토 32건과 같은 스레드의 2·3차 확인을 거쳐 고친 판이다(부록 A 끝). 계획 파일과 증거 사본은 승인 직후 옮겨 두기만 하고, 커밋은 구현 PR에 함께 넣는다.

## SKILL.md 섹션 구조와 각 절의 요지

위계는 옛 절을 물려받지 않고 지식의 종류로 자른다(단계로 자르면 미적 원리가 제안·작성·검수에 흩어진다). 아래 요지는 본문에 들어갈 판단이다. **요지 속 날짜·횟수·발화·실측명(괄호 안이든 밖이든)은 구현자용 근거이고 본문에 옮기지 않는다** — 본문에는 그 판단을 다시 도출하게 하는 이유 한 절만 남기고, 근거는 `docs/artist-design.md`로 간다. 기계가 판정하는 것(비율 적중, 실패 분류, 알파 유무, 장부 형식)은 CLI 출력이 소유하고 본문에 다시 쓰지 않는다. Claude가 이미 잘하는 것(HTML·CSS·타이포 기본기, 결과 이미지를 열어 보는 일)은 쓰지 않는다.

```
---
name: artist
description: (영어 한두 문장) Codex 내장 gpt-image로 이미지를 만들고, 성진과 합의하며 시안·검수·수정을 거쳐 최종 PNG까지 간다.
disable-model-invocation: true
allowed-tools: Bash(uv run "${CLAUDE_SKILL_DIR}/scripts/cli.py" *)
---
(도입) 하는 일 · 최종 판정자는 성진의 눈
## 성진과 합의하기
## 좋은 이미지의 원리
## 그림으로 만들까, 문서로 만들까
## 이 모델의 버릇
## 본다 · 고친다
## 도구
```

**도입.** 이미지를 만들어 주는 게 아니라 성진 마음에 드는 이미지에 도달하는 게 일이다. 판정은 성진의 눈이 하고, Claude의 판정은 그 눈이 빨리 결정하게 돕는다.

**성진과 합의하기.**
- 취향은 브리프가 아니라 이미지를 본 뒤 드러난다(9/4 "막상 만들고 나니까 생각이 좀 달라지네", 글 방향보다 "4가지 다 3장씩"). 그래서 생성 전에는 이미지로 확인할 수 없는 사실 — 용도와 이미지의 운명(완성·판·설계도), 고정 문구, 비율, 비워 둘 자리, 반드시 들어갈 대상 — 만 묻고 미적 방향은 이미지로 묻는다. 성진이 방향을 가져왔다면(레퍼런스·구체 아이디어) 그 방향도 사실이므로 글로 확인하고 그 방향으로 뽑는다. 방향이 없으면 서로 다른 가설 몇 개를 한 줄씩 보이고 바로 뽑아 이미지로 고르게 한다. 장수는 기본값일 뿐이다: 한 라운드가 동시 생성 상한(6장, 1~2분) 안에서 끝나야 성진이 기다리지 않고 나란히 비교한다. 성진이 더 원하면 따른다.
- 구도의 뼈대(구역 배분, 요소가 들고 남)가 바뀌는 라운드만 생성 전에 배치도(띠별 %)로 합의한다 — 사람은 완성 그림보다 빈 배치도에서 "여긴 이래야 한다"를 쉽게 말한다. 같은 뼈대 안의 수정은 바로 뽑는다.
- 생성 뒤에는 시트를 성진 앞에 두고, Claude 판정 2~3줄을 먼저 내고, 성진의 자유 서술을 받는다. 선택형 질문은 답이 진짜 갈림길일 때만 — 생성 직후의 "어느 걸로/다음은?"은 12번 넘게 닫혔다.
- 성진의 말을 **새 미적 제약으로 옮길 때**(불만을 금지나 요구로 바꿀 때) 그 해석을 한 줄로 확인받는다. 불만은 증상이고 처방은 추론이기 때문이다("다 파랑이라 식상" → "파랑 금지"였는데 목표 이미지가 파란 하늘을 썼다 / "나열 회피" → 개념 사물이었는데 "지나치게 디자인에만"). 이미 합의된 의도 안의 실행 수정(제목을 한 줄로, 배경을 밝게)은 확인 없이 고친다.
- 목표 이미지와 참조는 다른 역할이다: 목표는 결과를 대어 볼 기준(시트 맨 위)이고 모델에 넣지 않는다. 참조는 생성 조건으로 넣는다. 같은 파일일 수 있다.
- 장부 메모는 이번 작업에만 맞는 사실과 다음 작업에도 맞는 선호를 갈라 적는다 — 뒤의 것만 다음 작업이 `--like`로 물려받을 가치가 있다.

**좋은 이미지의 원리.**
- 빛·색·구도는 장면이나 브리프 안에 출처가 있어야 한다. 시험: 그 선택의 출처를 가리킬 수 있는가. 금지 목록이 아니다 — 축제 v5의 노을빛·골목 전구는 장면 안에 출처가 있어 성진이 골랐고, 법안 포스터의 금빛·시안 발광은 출처가 없어 실패했다. 모델과 Claude 자신이 끌려가는 기본값에 이름을 붙여 둔다: 밤·기술·축제·고급처럼 분위기를 부르는 주제에서 남색 밤 + 금빛·시안 발광 + 보케·떠다니는 입자 + 도시 야경(스킬 없는 Claude가 재즈 프롬프트에 "deep midnight navy … muted mustard gold accents"를 스스로 썼다). 그래서 Claude 자신의 초안도 같은 시험에 건다.
- 평범함은 모델이 카테고리 관습을 정확히 아는 데서 나온다. 서로 다른 방향이 필요할 때는 관습의 출처를 옮긴다(다른 업종의 관습, 다른 분야가 이미지를 기술해 온 언어, 글자 밖의 구조). 반대 조건: 관습이 곧 목적인 작업(의원실 시리즈의 익숙한 배치)은 배치를 지키고 위계와 절제로 품질을 낸다. 옮긴 관습이 늘 이기는 것도 아니다(영수증 축제는 밋밋했다).
- 이미지가 의도로 읽히는 건 몇 가지 결정이 화면 전체에 일관되게 적용될 때다(팔레트, 글자의 위계, 그림체, 가장자리를 쓰는 방식). 의도된 결함(질감)만으로는 평범함이 막히지 않는다 — 깨끗한데 평범하지 않은 포스터가 있다. 일관성을 깨는 건 깨는 것이 의미를 만들 때뿐이다(한 요소만 다른 색으로 시선을 모을 때).
- 결정이 개선인지 대체인지는 이번 작업의 기준선 — 장식 없이 한 줄로 넘겼을 때 모델이 낼 것 — 으로 판단한다. 기준선이 이미 브리프를 충족하면 새로움을 밀어붙이는 건 대체다. 애매하면 소박한 대조안을 같은 라운드에 같이 뽑아 나란히 본다 — 대조안에도 나오는 것은 결정이 아니다.
- 결정을 고른 뒤, 그 결정이 브리프가 지키라고 한 것을 밀어냈는지 되묻는다. 밀어냈으면 결정을 줄이지 말고 다른 축으로 옮긴다.
- 성진의 취향(개인 선호로 표시): 그래픽 디자이너가 일러스트로 정성스럽게 만든 느낌, 홍보물은 개념 장치보다 익숙한 배치를 잘 짠 쪽, 실사가 필요하면 생성한 가짜 실사가 아니라 실제 사진.
- 밀도 기준선 예시 2개(부록 B 원문)를 싣는다. 각 예시 아래에 그 프롬프트가 무엇을 고정했고(정확한 문구, 자리, 잉크 수, 핵심 장치) 무엇을 열어 뒀는지(세부 구성, 글자 모양) 한 줄로 단다. 눈금은 분량이 아니라 그 대비다 — 고르는 메뉴가 아니다.

**그림으로 만들까, 문서로 만들까.** 내용이 어디 실리나로 가른다. 그림이 내용이면 이미지 모델이 완성한다(작은 정보 줄은 Claude가 조판해 얹을 수 있다). 글자가 내용이면 Claude가 HTML로 짜고 GPT는 요소만 만든다(투명 배경, 요소 하나에 생성 하나 — 묶어 뽑으면 낱개로 가르기 어렵다). 사이면 섞는다. 실사진은 생성하지 않고 원본에 보정만 건다. 이유: 이미지 모델은 글자를 지어내고 깨뜨리며 정확한 자리 배분이 안 되고, 템플릿은 매번 문구가 바뀐다. 단, 글자가 그림과 얽히면(획이 사물이 되고 형상이 제목 앞을 지나가면) 그 글자는 모델이 그린다.

**이 모델의 버릇.** 사실만, 각 줄에 그 사실이 바꾸는 행동을 붙인다. 소수 표본은 "관측된 범위의 경험칙"으로 쓰고 법칙처럼 쓰지 않는다. 후보(구현 6단계 R 재검증 결과로 넣고 뺀다):
- 앞쪽에 쓴 대상이 화면을 더 차지한다 → 주인공을 앞에(R9).
- 비율은 첫 문장에 밝히면 맞았다. 픽셀 치수 문장은 이득이 없었다(이번 세션 44장 중 43장, 유일한 이탈이 픽셀 치수를 붙인 쪽).
- 크기는 분수 대신 위치로(R1) / 자르기는 주제보다 지면에 걸 때 지켜진다(R2) / 물성을 공정보다 앞에(R3) / 매체는 하나만 적용된다(R4) / hex 색은 안 먹는다 → 이름과 대비로(R5).
- 시키지 않은 글자·기관명·서식 칸·읽힐 듯한 가짜 글자를 지어낸다 → 출처·인용·숫자는 자리만 잡거나 문구를 준다, 검수에서 찾는다(R6·R7).
- 짧은 한글은 대체로 정확하지만 실험적인 글자 구성(노선도 획)은 글자를 깨뜨렸다.
- 참조 이미지는 색·서체 같은 가족 유사성을 강하게 옮기고 때로 베낀다 → 베끼면 참조를 빼고 말로(R8).
- 정답이 있는 형태(국기 괘·상징)는 이름·개수 대신 구조로 서술했을 때 맞았다(옛 장부 관측).
- 참조 수정을 거듭하면 질감과 의도된 거칠기가 "더 잘 그린" 쪽으로 침식됐다(옛 장부 관측).
- 거부는 확률적이고 무엇이 막히는지는 문서가 알 수 없다 — 막힐 수 있다고 말하고 대안을 함께 낸다. 처방은 `generate`의 실패 줄이 말한다.

**본다 · 고친다.**
- 모든 장을 본다(한 프롬프트의 장들도 서로 다르다). 글자·상징·손·얼굴·지어낸 글자는 `zoom`으로 원본 해상도에서 본다 — 작은 결함은 한 번 훑어서는 놓친다(건곤감리 어긋남은 성진이 먼저 잡았다).
- 측정은 눈이 체계적으로 틀리는 넷에만 쓴다: 여러 장 사이 면적 비교, 지면과 잉크의 명도 대비, "허전하다"의 원인(가장자리 접촉인가 잉크 양인가), 팔레트 준수. 숫자는 성진이 결정하는 근거로 보여 준다 — 인상은 행동을 못 바꾸고 숫자는 바꾼다.
- 수용 여부를 바꿀 약점이 보이면 근거와 함께 먼저 말한다 — 성진은 불만을 말로 하기 전에 느끼고, 그걸 먼저 짚는 게 아트 디렉터의 일이다. 그런 약점이 없으면 충족한 기준과 남은 불확실성을 말한다. 없는 결함을 지어내지 않는다.
- 고치는 길 셋을 고르는 기준: 구성이 틀렸으면 다시 뽑기 / 구도는 맞고 한 요소만 바꾸면 참조 수정(바꿀 것 하나 + 지킬 것을 낱낱이) / 작은 결함이면 참조 수정본에서 그 영역만 승인본에 `patch`. 참조 수정은 인페인팅이 아니라 전체 재생성이라 픽셀 보존을 약속하지 않는다. 결함이 컨셉인 작업은 수정을 쌓지 말고 원본 프롬프트를 고쳐 다시 뽑는다.

**도구.** `--help`가 지도다. 프롬프트는 장부(`job.json`)에만 있고, 시트는 장부에서 매번 다시 만든다. 실패 줄이 다음 행동을 말한다.

## CLI 구조

호출은 `uv run "${CLAUDE_SKILL_DIR}/scripts/cli.py" <command> …` 한 줄. 명령은 한 층이고 각 `<command> --help`가 자기 인자·출력·실패·종료 코드를 혼자 다 말한다(`--help`만 텍스트). stdout은 결과 JSON 하나 — 싼 신호(`summary`, 다음 행동) 먼저, 비싼 상세는 파일 경로. stderr는 진행·진단. 종료 코드: 0 성공 · 1 실행했으나 결과 없음(JSON `error`) · 2 인자 오류(stdout에 `{error, help}`) · 3 `doctor`가 막는 문제를 찾음. `<job>`은 짧은 이름 또는 경로.

| 명령 | 하는 일 | 주요 인자 | 출력 · 실패 |
|---|---|---|---|
| `init` | 장부를 만든다 | `<job> --request T [--aspect W:H] [--purpose T] [--text S]… [--target IMG]… [--note T]… [--like <job>]` | `{job, sheet, inherited, legacy_notes?}`. 장부가 있으면 덮지 않고 1. `--aspect`는 `--like`가 주지 않으면 필수(2). `init --note`는 `job` 범위 |
| `add` | 생성 전에 버전의 의도를 기록한다 | `<job> --direction NAME --method generate\|edit [--ref IMG]… [--aspect W:H\|none] [--transparent] [--parent N] [--change T]`, 프롬프트는 stdin | `{version}`. `edit`인데 `--ref`가 없으면 2. `--aspect`의 기본은 brief, 요소는 `none` |
| `generate` | 기록된 버전을 생성한다 | `<job> --version N [--version M]… [--n K]` | 요청 총량(버전×K)은 큐로 받고 동시 실행은 6. 변형마다 stderr 한 줄, 끝에 `{summary, results:[{version, attempt, file?, status, w?, h?, aspect_ok?, alpha?, verbatim?, error?}], sheet}`. 1장 이상 성공이면 0, 전부 실패면 1 |
| `record` | 본 것과 결정을 적는다 | `<job> [--version N [--critique T] [--chosen FILE]] [--note T [--reusable]] [--final FILE [--export PATH] [--crop x,y,w,h%] [--size WxH] [--format png\|jpg]]` | `{written, exported?}`. `--chosen`은 그 버전의 `ok` 시도 파일만, `--final`은 파일로 소속 버전을 찾고(`--version`을 함께 주면 일치해야) `ok` 시도 파일만 — 아니면 1. 내보내기는 검증 → 자르기 → 크기 맞춤 → 임시 파일 → 목적지 이동이 다 성공한 뒤에 장부에 반영한다(실패하면 장부의 final·export 기록은 그대로, 1). 자른 뒤 비율이 `--size`와 1% 넘게 다르면 1, 같은 경로가 있으면 덮지 않고 1 |
| `show` | 장부 요약(Claude용) | `<job>` | `{summary, versions:[{v, direction, method, ok, failed, chosen?, critique_first_line?}], failures_by_kind}` |
| `sheet` | 시트를 다시 만들고 연다 | `<job> [--open]` | `{sheet}` |
| `zoom` | 원본 해상도 타일로 자른다 | `<img> [--grid 2\|3] [--region x,y,w,h%] [--job J]` | `{tiles:[{path, x, y, w, h}]}`. 영역을 먼저 자르고 격자로 나눈다, 리샘플 없음. 저장은 작업 폴더의 `.inspect/<파일명>/<실행 시각>/`(작업 밖 이미지는 이미지 옆 `.inspect/`) — 재실행이 이전 타일을 덮지 않는다 |
| `measure` | 측정 넷 | `<img>… --axis zones\|contrast\|edges\|colors [--bands 0,8,30,70,100] [--box x0,y0,x1,y1%] [--target-color HEX] [--job J --version N]` | `{results:[{file, axis, values, fingerprint}]}`. `--job`이면 장부에 측정 기록으로 덧붙인다 |
| `patch` | 고친 영역만 승인본에 합성 | `<job> --base FILE --from FILE --region x,y,w,h% [--feather PX] [--direction NAME]` | `{version, file, outside_diff}`. `--base`·`--from`은 이 작업에 등록된 `ok` 시도 파일이어야 하고(아니면 1), 새 버전의 부모는 `--base`의 버전이다. 두 이미지 크기가 다르면 1. 영역 밖 차이(`outside_diff`)는 수치로만 보고하고 판정은 Claude가 확대해서 한다 |
| `render` | Claude가 쓴 HTML을 PNG로 | `<job> --html FILE --size WxH [--scale 1\|2] [--direction NAME] [--parent N]` | `{version, file, px:[W×scale, H×scale]}`. 누락 자산·안 실린 글꼴·페이지 오류가 있으면 1 + 목록 |
| `doctor` | 실행 환경 점검 | — | `{codex:{version, logged_in}, chrome, fonts:[{family, weights}], data_link}`. 막는 문제가 있으면 3 |

**생성(`generate`).** 옛 `generate.py`의 검증된 동작을 옮긴다(이번 세션 0.159·0.160에서 같은 봉투로 동작): "그대로 넘기라"는 봉투로 `codex exec --json --skip-git-repo-check -s read-only --output-schema … -o … -`(stdin)에 넘긴다. 참조는 봉투에 `referenced_image_paths`(작업 폴더 기준 → 절대 경로), 투명은 `transparent_background: true` 지시로 넣고, 재시도 봉투에도 그대로 둔다.
- verbatim(Codex가 마지막 JSON에 적은 `prompt_passed` 자기보고와 원문 비교 — 실제 도구 인자 관측이 아니다): `exact`·`normalized`(공백만 다름)는 통과, `unverified`(보고 없음)는 통과하되 경고, `mismatch`는 더 강한 봉투로 한 번 재시도하고 그래도 `mismatch`면 `prompt_altered`(파일은 남기되 고를 수 없음). 첫 실행과 재시도의 시간·증거를 둘 다 남긴다.
- 실패 사유는 롤아웃(`$CODEX_HOME/sessions/**/rollout-*<thread_id>.jsonl`)에서 구조로 읽는다(옛 `_parse_failure`의 이중 JSON·`Some(...)` 처리, 한 스레드의 여러 실패 중 `moderation_stage: output`을 우선, 횟수는 `tries`). 실패 줄에 분류·사유·처방을 같이 찍는다(stage `output` = 결과 이미지가 막힘 → 재시도만 레버, `input` = 프롬프트를 고침, 미상 = 원문을 읽고 판단).
- 상태: `ok · running · interrupted · refused · executor_error · timeout · prompt_altered · path_mismatch · silent_no_image`. `path_mismatch`(보고된 이미지가 그 thread 디렉터리 밖)는 파일을 남기되 고를 수 없다. `detail`은 `code, message, moderation_stage, categories, returncode, events_file, agent_message, tries`를 `codex/`가 내부 타입으로 바꿔 담는다.
- 파일명은 시도마다 영구 고유: `v{N}-{k}.png`(k는 그 버전의 누적 시도 번호, 재생성해도 이어서 증가). 어떤 실행도 이전 이미지·로그를 덮지 않는다. 실행 로그는 `.runs/<run_id>/`.
- 비율: 버전의 `aspect`(기본 brief, 요소는 `none` → 검사 안 함)와 PNG 크기 비교, 허용 1%. `--transparent`면 알파 채널 유무·투명 비율을 보고하고 알파가 없으면 경고.
- 타임아웃 기본 300초, 초과하면 프로세스 그룹을 종료하고 행을 `timeout`으로 닫는다. 첫 생성 전에 `codex login status`를 확인한다.

**장부 쓰기.** 모든 쓰기는 작업별 잠금 파일(`job.json.lock`, `fcntl.flock`) 아래에서 읽고-고치고-쓴다(원자적 rename). `running` 행은 `pid`·시작 시각을 갖고, 같은 시도 ID로 한 번만 결과로 바뀐다. 완료된 시도 행은 바뀌지 않는다. 장부를 읽을 때 `pid`가 죽은 `running` 행은 `interrupted`로 닫는다.

**시트.** 이미지 등록은 자동이다: `generate`·`patch`·`render`가 결과를 장부에 쓰는 순간 시트가 다시 만들어지고, Claude는 이미지를 손으로 등록하지 않는다. Claude가 직접 적는 것은 판단(판정·선택·메모·최종)뿐이고 그것도 `record`가 쓰는 순간 시트에 반영된다. 고정 레이아웃: 목표 이미지(맨 위 고정) · 브리프 · 버전마다 이미지 줄(크기·비율 표시, 선택본 강조, 클릭 확대) · 판정 · 접힌 프롬프트·참조·입력 · 접힌 실패 · 측정 · 최종. 작업의 첫 `generate`/`render` 때(실패해도) 브라우저로 연다(장부에 `sheet_opened` 기록, `sheet --open`은 다시 연다). 열린 탭은 열려 있는 동안 몇 초마다 스스로 다시 읽되 스크롤 위치를 보존하고(localStorage) 확대 보기 중에는 미룬다 — 그래서 탭 하나가 라운드를 넘어 살아 있다. 이미지는 상대 경로로 참조한다(base64 금지).

**렌더(`render`).** HTML은 작업 폴더 안에 있어야 하고, 자산 참조는 작업 폴더 안의 로컬 파일만 허용한다 — `src`·`href`(스타일시트), 인라인 `<style>`과 연결 CSS의 `url()`. 작업 폴더 밖 경로와 원격 URL은 거부한다(쓰려면 먼저 작업 폴더로 복사; 글꼴은 설치된 것을 이름으로). 렌더 직전에 HTML과 참조 파일 전부를 작업 폴더 기준 상대 구조 그대로 `renders/v{N}/` 아래에 복사하고, 렌더는 그 스냅숏에서 한다 — 그래서 스냅숏이 원본 없이 그 버전을 재현한다. `--size`는 CSS 뷰포트, 출력 픽셀은 size×scale. `document.fonts.ready`와 모든 이미지 decode를 기다린다(제한 30초). 글꼴 실패의 기준은 선언된 대체 목록이 아니라 **실제로 렌더에 쓰인 글꼴**이다(`document.fonts.check`는 없는 family에도 true를 줄 수 있어 쓰지 않는다): 텍스트가 있는 요소마다 Playwright의 CDP 세션으로 `CSS.getPlatformFontsForNode`를 불러 실제 쓰인 플랫폼 글꼴과 글리프 수를 받고, 계산된 font-family의 첫 family가 그 목록에 없거나 글리프 일부가 다른 글꼴로 대체됐으면 요소·의도한 family·실제 글꼴을 목록으로 내고 1. 테스트: 없는 family 이름, 한글이 없는 라틴 글꼴에 한글 텍스트 — 둘 다 실패해야 한다. 누락 자산·콘솔 오류도 1. `doctor`가 설치된 글꼴의 CSS family·weight 목록을 준다(같은 파일도 family 이름 표기가 여럿일 수 있다).

**패치(`patch`).** 영역(%)을 픽셀로 바꿀 때 시작은 내림·끝은 올림. feather는 영역 안쪽으로만 번진다 — 그래서 영역 밖 픽셀은 디코딩된 RGBA 값이 승인본과 동일하다(파일 바이트가 아니라 픽셀). `outside_diff`는 영역 밖을 128px로 줄인 명도의 평균 절대 차이로, 구도 이동의 단서로만 쓴다.

**측정(`measure`).** 공통 전처리: 짧은 변 900px로 Lanczos 축소 → sRGB를 CIE L*a*b*(D65)로 변환 → 알파 128 미만 픽셀은 모든 축에서 제외. 지면 L* = L* 채널을 가우시안 블러(σ=1px)한 뒤 1단위 구간 히스토그램의 최빈값, 잉크 = 블러 전 L*가 지면과 10 넘게 차이 나는 픽셀. 최빈 구간이 측정 픽셀의 15% 미만이면 `ground_unreliable: true`를 붙인다(사진·다색 지면 — 이때 zones·contrast·edges는 참고용). zones = `--bands`(높이 %, 경계 포함은 위쪽) 띠별 잉크 비율 + 잉크가 있는 첫·마지막 행(%), `--box`면 그 상자 안 잉크 비율. contrast = 잉크 평균 L* − 지면 L*(부호 포함). edges = 짧은 변 1% 폭 테두리의 잉크 비율, 전체와 변별. colors = 짧은 변 200px로 다시 줄인 Lab 픽셀에 k-means(k=6, k-means++, 시드 0, 반복 20)의 군집 중심(hex)과 면적 비율, `--target-color`면 가장 가까운 군집까지 ΔE2000. 위 상수 전부를 지문에 넣는다.

**상속(`init --like`).** 출처 장부의 schema(1·2·3)를 읽어 비율·목표, 그리고 `reusable` 범위 메모만 가져온다(옛 `brief.target_images` → `targets`). 범위가 없는 schema 1·2 메모는 자동 상속하지 않고 출력의 `legacy_notes`로만 보여 준다 — Claude가 그중 다음 작업에도 맞는 것을 `record --note … --reusable`로 다시 적는다. 목표 경로는 출처 작업 폴더 기준으로 풀어 절대 경로로 저장한다. 명시한 `--aspect`가 상속을 이기고, 명시한 `--note`·`--target`은 상속분 뒤에 붙는다. 옛 장부의 나머지(버전·시트)는 다루지 않는다.

## 장부(job.json) 모양

```
{ "schema": 3, "id", "created", "sheet_opened"?,
  "brief": { "request", "aspect", "purpose"?, "text"?: [], "targets"?: [], "notes"?: [ { "text", "scope": "job|reusable", "at" } ] },
  "versions": [ {
      "v", "direction", "method": "generate|edit|patch|render", "created", "parent"?: N, "change"?,
      // method별 입력 — generate/edit: "prompt", "refs"(edit는 1개 이상), "aspect", "transparent"
      //                 patch: "inputs": {base, from, region_px, feather}  render: "inputs": {html_snapshot, size, scale}
      "attempts": [ { "id", "status", "pid"?, "started", "elapsed_s"?, "file"?, "w"?, "h"?, "aspect_ok"?, "alpha"?,
                      "verbatim"?, "retried"?, "thread_id"?, "detail"? } ],
      "critique"?, "chosen"?: "<그 버전 ok 시도의 file>" } ],
  "measurements": [ { "file", "version"?, "axis", "bands"?, "box"?, "target_color"?, "values", "fingerprint", "at" } ],
  "final"?: { "file", "exported": [ { "path", "crop"?, "size", "format", "at" } ] } }
```

- `direction`은 `add`에선 필수, `patch`·`render`에선 생략 시 부모 버전에서 물려받는다(`render`에 부모가 없으면 필수). `parent`는 버전 번호, `patch`의 승인본·고친 본은 `inputs`에 파일로 적는다.
- patch·render도 시도 행을 하나 갖는다(실패하면 `executor_error`와 사유).
- 알 수 없는 키는 오류(스키마는 결정으로만 자란다). 형식 검증 실패면 쓰기를 거부한다.

**가짜 codex 시나리오(3단계).** `PATH` 앞에 두는 실행 파일. 실제 argv(`exec --json --skip-git-repo-check -s read-only --output-schema F -o F -`)와 stdin 봉투를 받고, 임시 `CODEX_HOME`에 `thread.started` 이벤트·`-o` 마지막 메시지·`generated_images/<thread_id>/*.png`·`sessions/YYYY/MM/DD/rollout-…-<thread_id>.jsonl`을 실제 형태로 쓴다. 환경 변수로 고른다: `ok` · `normalized` · `unverified`(prompt_passed 없음) · `rewrite→ok`(재시도에서 정상) · `rewrite×2` · `refuse_output` · `refuse_input` · `refuse_unknown`(stage 없음) · `refuse_multi`(한 롤아웃에 실패 여러 개, `Some("{…}")` 이중 JSON) · `exit_nonzero` · `bad_json` · `path_fallback`(보고 경로 없음, thread 디렉터리에 PNG) · `path_outside`(→ `path_mismatch`) · `hang`(타임아웃: 자식까지 종료되고 행이 닫히는지) · `logged_out`(doctor·preflight).

**R 재검증표(6단계).** 각 후보 문장마다 같은 목표·한 변수·판정법·대조를 맞춘다. 각 조건 3장. 채택 조건은 행마다 "채택" 칸이 정한다 — 공통 규칙은 "후보 문장이 처방하는 쪽이 의도를 2/3 이상 달성하고, 처방하지 않은 쪽보다 낫다". 채택해도 관측 범위의 경험칙으로 쓴다. 표에 없는 후보 중 국기·상징의 구조 서술과 반복 편집의 질감 침식은 옛 장부(광복절 v6→v7, 위안부 v2→v4·v5)의 증거를 인정해 재측정을 보류하고 "관측"으로 쓴다. 어느 실험도 없는 후보는 본문에 쓰지 않는다.
