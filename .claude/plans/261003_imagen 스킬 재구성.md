# imagen 스킬 재구성 — 계획

> 계획 모드가 읽는 원래 경로 `.claude/plans/users-seongjin-coding-claude-artist-cla-keen-wadler.md`는 이 파일을 가리키는 심볼릭 링크다. 구현 0단계에서 링크만 지운다. 구현은 이 문서를 읽는 새 세션에서 한다.

## Context

성진(의원실 홍보 비서관, 디자인 어휘는 없지만 결과는 정확히 판정)은 `/imagen`으로 Codex image_gen(gpt-image-2) 이미지를 만든다. 대화하며 시안을 옵션으로 보이고, 피드백을 반영한다. 쓰임은 두 가지다. 하나는 단독 작업(한글날 포스터)이고, 다른 하나는 다른 작업에 쓸 소재를 뽑는 일(카드뉴스 프로젝트의 5·18 탑 펜화)이다. 성공 기준은 이미지 품질 하나다.

성진이 물었다: "SKILL.md에는 합의 원칙을 담고, 좋은 이미지를 위한 프롬프트 작성 원칙은 interface(CLI)로 옮기는 게 좋지 않은가? 프롬프트도 CLI의 파라미터니까." 이어서 두 가지를 더 말했다. 스킬에 너무 많이 넣지 말 것(Claude가 유연하게 대응한다). 그리고 결과물을 스킬 안 `data/`에 쌓아 예시로 쓸 것. 또 지금 SKILL.md가 skill-maker 프레임을 철저히 따르는지 물었다.

결론은 세 가지다.
- **절반은 옮긴다.** gpt-image-2가 프롬프트를 읽는 방식은 CLI help로 옮긴다. 어떤 이미지를 노릴지에 대한 판단은 SKILL.md에 남긴다.
- **본문을 감사 결과대로 고친다.** Claude와 Codex의 독립 감사 모두 "대체로 충실하나 철저하지는 않다"고 판정했다. 지적된 곳은 예시가 틀처럼 쓰인 점, help 사본, 이유보다 강한 절차다.
- **`data/`를 스킬 안의 빈 폴더로 바꾼다.** 결과물이 쌓이면 비슷한 작업에서 예시로 본다.

새 기능은 `add`의 비율 경고 하나뿐이다. 나머지는 옮기고, 지우고, 고쳐 쓰는 일이다.

## CLI 변경

`cli.py`는 명령 표면(파서·help·디스패치)만 소유한다. 그래서 help 문장은 `cli.py`에 두고, 검사 로직은 `codex` 단위에 둔다. help는 영어다(D8). 줄바꿈 원칙도 지킨다. 항목 하나가 한 줄이고, `RawDescriptionHelpFormatter(width=1000)`라 접히지 않는다. 구현 뒤 실제 `--help` 출력으로 확인한다.

**`add`의 description.** 지금은 요약 한 줄이다. `command()` 헬퍼에 별도 description을 받게 해서 요약 아래에 아래 블록을 둔다. 사용법 바로 다음에 나오므로, help를 `| head`로 잘라 읽어도 남는다.

```
Record a version's intent before generating it. The prompt is read from stdin.

How the model behind codex's image_gen (gpt-image-2) reads a prompt: tendencies observed on this path, not laws; when a result disagrees, trust the result.
  - Write the prompt as English prose.
  - State the aspect ratio as its own sentence at the start ("Portrait 4:5 aspect ratio, taller than it is wide."); the ratio is set only by the prompt, and pixel sizes add nothing. add warns when the first sentence does not state this version's aspect.
  - Whatever is named first takes more of the frame and the first look, so name the subject first.
  - Listing several media keeps only some of them; to mix, name one medium and give it another's quality ("an oil painting with the flatness of a screenprint").
  - Anything not supplied gets invented (organisation names, domains, dates, places, numbers, slogans), differently in every image: give every string the image must show, Korean included, inside double quotes exactly as it must read, and close with "no other text"; for a source, quotation or figure, give the wording or only reserve its place.
  - Asked for unreadable marks, it writes readable-looking fake Hangul; a surface that must carry no text has to be called blank.
  - Short Hangul strings come out mostly right; lettering whose strokes turn into objects breaks the letters.
  - A flat ground given as a hex colour comes out close to it; colour names and comparisons drift further.
  - A shape with one right answer (a flag's trigrams, a symbol) comes out right when its structure is described, not its name and count.
```

**인자 help (각 한 줄).**
- `--ref`: `image passed to the model with the prompt; repeatable. The model carries over a reference's palette, lettering and layout, down to its date format, even when told to use it for style only. When a new composition was wanted and the reference's layout came along, drop the reference and put the wanted qualities into words; with --method edit keeping the composition is the point.`
- `--method`: `generate: from the prompt alone (refs optional, as style or content references); edit: rework the --ref image(s), at least one required; the prompt names the one change and lists everything that must stay, since "keep everything else the same" alone does not hold it`

**`add` epilog.** 첫 줄을 `output: {"version": N, "warnings"?: [...]}`로 바꾼다. 다음 문장을 더한다: `warnings flags an aspect ratio that is missing from, or different in, the prompt's first sentence (not checked for --aspect none); the version is recorded either way.` 실패 줄은 그대로 둔다.

**`init` epilog.** `--like` 문단 끝에 다음을 더한다: `Old notes often prescribe giving sizes by position instead of fractions, cropping by the ground instead of the subject, and that hex colours do not work; measured on the current model, none of the three held, so do not carry them into a new job as constraints.` hex에 대한 긍정적 관측은 `add` description에만 둔다(중복 방지). "주제에 거는 크롭이 낫다"처럼 반대 처방으로 일반화하지 않는다. SKILL.md L40의 "크롭을 배경에 건다"는 다른 판단(필수 요소를 밀어낸 결정을 다른 축으로 옮기기)이라 충돌시키지 않는다.

**비율 경고.** `codex` 인터페이스에 `prompt_warnings(prompt: str, aspect: str) -> list[str]`를 더하고 `__all__`에도 넣는다. 내부 모듈 배치는 구현자가 정한다.
- `aspect == "none"`이면 `[]`.
- 첫 문장: 첫 `.`·`!`·`?`(뒤따르는 닫는 따옴표·괄호 `"` `'` `)` `”` `’`까지 포함) 다음에 공백이나 끝이 오는 곳까지. `1.5` 같은 소수에서는 끊지 않는다. `Dr.` 같은 약어는 처리하지 않는다. 그런 경우 경고가 한 줄 더 날 뿐 버전은 기록되므로, 이 한계를 받아들인다.
- 첫 문장에서 `(\d+)\s*:\s*(\d+)`로 두 값이 모두 양수인 비율만 모은다.
- 하나도 없으면: `the first sentence states no aspect ratio; image_gen takes the ratio only from the prompt, so state {aspect} there`
- 버전 비율과 교차곱이 다른 것이 하나라도 있으면(`8:10`은 `4:5`와 같다): `the first sentence states {mismatches joined by ", "} but this version's aspect is {aspect}`. 같은 것과 다른 것이 함께 있어도 경고한다.
- `record.add`는 버전을 기록한 뒤 경고가 있을 때만 출력에 `"warnings"`를 붙인다(`init`의 warnings와 같은 방식). 거부하지 않는다.
- 이 검사는 숫자 쌍의 유무·일치만 본다(`"04:05"` 같은 시각 표기도 비율로 읽힐 수 있다). help 문구는 이 범위만 말한다.

**구조 테스트 픽스처.** `tests/test_structure.py`의 `broken` 픽스처는 `shutil.copytree(SKILL, …, symlinks=True)`로 스킬 폴더를 통째로 복사한다. `data/`가 실제 폴더가 되면 쌓인 작업까지 테스트마다 복사된다. **최상위 `data`만** 복사에서 빼는 ignore를 쓴다(`ignore_patterns("data")`는 모든 깊이에 걸리므로 쓰지 않는다). `check_tree()`는 `data` 존재를 요구하지 않으므로 다른 검사에는 영향이 없다.
