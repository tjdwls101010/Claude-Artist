## 구현하며 계획에서 달라진 것

- `numpy`를 의존성에 더했다. 측정 정의(Lab D65 실수 연산, σ=1 블러, k-means, CIEDE2000)를 순수 파이썬으로 하면 이미지당 수 초에서 수십 초가 걸리고, Pillow의 LAB 모드는 D50·8비트 양자화라 1단위 L* 히스토그램 정의를 지킬 수 없다.
- 공용 헬퍼 `errors.py`(종료 1·2의 예외)와 `regions.py`(퍼센트 → 픽셀, 시작 내림·끝 올림 한 규칙)를 더했다. 같은 반올림 규칙을 `zoom`·`patch`·`record --crop`·`measure --box`가 함께 써야 해서다.
- `record --target`을 더했다. 작업 중간에 목표 이미지가 나타나는 경우 장부에 넣을 길이 없었다(옛 스킬도 같은 구멍을 한 번 막았다).
- `doctor --fonts hangul|all`(기본 hangul)을 더했다. 설치 글꼴 전부(이 머신 수백 family)를 매번 stdout에 싣는 비용을 피한다.
- `init`·`add`·`show`는 `record.py`에 둔다. 장부에 의도를 쓰는 일이고, 시트 재빌드 간선(`record→sheet`)을 함께 쓴다.
- 글꼴 판정은 이름 비교가 아니라 탐침 비교다. CDP `CSS.getPlatformFontsForNode`는 CSS "Paperlogy"로 제대로 맞은 글자도 legacy family 이름("Paperlogy 7 Bold")으로 보고해, 이름을 비교하면 정상 렌더가 실패한다. 그래서 같은 글자를 `"<family>", "Apple SD Gothic Neo"`와 `"<family>", "AppleMyungjo"`로 한 번씩 더 그려 두 결과가 같은 face면 그 family가 실제로 그 글자를 그린 것으로 본다. `doctor`의 글꼴 목록도 같은 탐침으로 CSS가 실제로 해석하는 이름만 남긴다(예: 파일 이름은 Cafe24Shiningstar지만 CSS 이름은 "Cafe24 Shiningstar OTF").
- CDP `CSS.enable`은 인라인 스타일의 원본을 file:// 문서로 다시 요청해 "Unsafe attempt to load URL" 콘솔 오류를 남긴다. 그래서 콘솔·요청 실패 수집은 스크린샷 시점에 멈추고 글꼴 탐침은 그 뒤에 한다.

## 기본값 교정 줄

## 버린 대안

- API 경로(Images API 직접 호출): 정확한 크기·마스크·2.5 모델을 주지만 성진이 D2에서 기각했다. Codex 구독 안에서 끝나고 지금 품질로 충분하다는 판단.
- references 분리: 합본이 500줄 아래라 한 파일(D16·17).
- 배치 스케치를 참조 이미지로: M4에서 이득 없음.
- 옛 측정 축 셋(flat-fill·palette-distance·hue-count): 축 이름과 실제로 재는 것이 작업마다 어긋났다. zones·contrast·edges·colors 넷만 남겼다.
- "비율은 끝에서 반복해야 한다": 첫 문장만으로 2/2, 첫 문장+픽셀 치수 7/7 — 필수가 아니다. 다만 끝 반복이 해가 된 적도 없다.
- 옛 린터(check_prompt.py): 형태가 닫힌 것만 잡고, 그것도 지금 모델에서 실패를 막은 증거가 없다. 프롬프트 판단은 원리 절이 맡는다.
